Pattern

Dialogs & overlays

Interrupt only when a decision cannot wait.

WCAG 2.2 AAStatus: stable
  • Overview
  • When to use
  • Structure
  • States
  • Responsive
  • Accessibility
  • Content

Overview

The brochure has no overlays. Apps use dialogs for confirmations, menus for secondary actions, tooltips for icon names.

When to use

  • Dialog: a decision now.
  • Drawer: a side task with context.
  • Popover: a small form anchored to a control.
  • Menu: several actions on one object.

Structure

Delete this request?

This cannot be undone.

A confirmation.
HTML
<div class="dialog__panel" style="position: static; animation: none; border-radius: var(--radius-lg);"><div class="dialog__header"><h3 class="dialog__title">Delete this request?</h3></div><div class="dialog__body"><p>This cannot be undone.</p></div><div class="dialog__footer"><button class="btn" type="button">Keep it</button><button class="btn btn--danger" type="button">Delete request</button></div></div>

States

  • Default, busy, invalid, failed.

Responsive

  • Bottom sheets under 640px.

Accessibility

  • Focus trapped and restored; page behind inert; Esc closes.

Content

  • Title asks, buttons answer.
