Button

Buttons let people act: send a request, start a project, try again. One primary button per view says what matters most.

WCAG 2.2 AAStatus: stableNative <button>

Overview

  • Use a button when activating it changes something: it submits, sends or opens. Use a link when it only goes somewhere.
  • Primary is the one action the view exists for. On the brochure page that is Send request; the header's Start a project is a link styled as a primary button because it jumps to the form.
  • Secondary (the default look) is any other action. Ghost sits in dense surfaces. Link is a low-emphasis action inside text. Danger appears only inside a confirmation.

Anatomy

  1. Leading icon (optional)1.25em, inherits the label colour, aria-hidden.
  2. LabelVerb phrase, sentence case; it is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-md, 1px border.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves.

Primary, secondary, ghost, link, danger.

Sizes

Medium is the default. Large is the contact form's submit, where the button is the point of the page. Small lives in tables and toolbars.

Heights --control-height-sm/md/lg; padding --space-3/4/6.
HTML
<button class="btn btn--primary btn--sm" type="button">Small · 32px</button><button class="btn btn--primary" type="button">Medium · 40px</button><button class="btn btn--primary btn--lg" type="button">Large · 48px</button>

States

Pointer and focus states are forced with data-state so they can be reviewed without a mouse; real pages get them from :hover, :focus-visible and :active. Everything else uses the real attribute.

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy="true" and ignores clicks. The contact form's sending state uses it.
  • Disabled uses the native attribute. Prefer leaving Send request enabled and showing what to fix on submit, as the invalid mock does.

Responsive behaviour

  • Below 768px a form's primary button may go full width with .btn--block; on the brochure it stays inline because the hint sits beside it.
  • Labels never truncate. A label that wraps at 360px is too long.
  • Medium and large buttons exceed 44px of touch height including spacing.

Theming

The button reads four component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover) that alias semantic tokens. In light, primary is Evergreen Ink with Linen text. In dark it reverses: a Linen button with ink text, exactly as the reversed logo does.

Accessibility

Role and pattern

Native <button>, or <a href> when it navigates (the header's Start a project). No ARIA role needed.

Keyboard

KeyAction
TabMoves focus to the button.
Enter, SpaceActivates it. A link-button responds to Enter only.

Focus

The shared gold ring, 2px with a 2px offset, on :focus-visible only.

Labelling

The visible label is the name. Icon-only buttons need aria-label with a verb and the object.

Motion

Background transitions over --duration-fast; active nudges 1px down. Reduced motion zeroes both through the tokens.

Touch

40px and 48px heights clear the 24px minimum; small buttons sit only inside larger tappable rows.

Content

  • Verb phrases in sentence case: Send request, Start a project, Try again. Never Submit or OK.
  • Retry buttons say what is retried when the context is not obvious.
  • Keep labels to three words or fewer.
